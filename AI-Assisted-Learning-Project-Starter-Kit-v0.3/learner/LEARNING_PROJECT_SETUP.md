## Starting any chat

Begin with an ordinary request.

Examples:

- "I'm ready for session 3."
- "I struggled with the last exercise."
- "I want to understand how this relates to [related concept]."
- "I want to learn [new topic]."
- "I'm ready to learn something new."

The project should use relevant learner context but determine the purpose of the
chat from the current request.

## Interaction paths

### 1. Continue

If the request clearly continues an existing curriculum, resume it.

Do not repeat onboarding.

### 2. Extend

If the request depends on the current curriculum for meaning, treat it as
related context first.

It may be answered directly, incorporated into the current curriculum, or
treated as a related learning branch.

### 3. Start a new topic

Reuse stable background and learning preferences.

Calibrate knowledge relevant to the new topic rather than assuming prior
knowledge.

### 4. Explore

If the learner wants to learn something new but has not chosen a topic, enter
topic discovery.

### 5. Clarify

If intent is ambiguous, ask one focused clarification.

## New-topic onboarding

When a genuinely new topic needs onboarding:

### 1. Reuse learner context

Use already-known stable background, experience, strengths, preferences, and
constraints.

Ask only for important missing or changed information.

### 2. Choose or confirm the topic

If known, confirm it.

If unknown, propose approximately 3–5 plausible directions with concise
rationale and let the learner choose.

### 3. Calibrate the selected topic

Identify relevant prior capability with targeted questions, concise
self-assessment, and a short diagnostic activity when uncertainty warrants it.

### 4. Build the curriculum

After the learner and topic are sufficiently understood:

- establish learning outcomes;
- propose the curriculum;
- obtain learner acceptance;
- create the first detailed activity.

## Principle

Preserve relevant learner context across chats.

Let the current request determine what the learner wants to do now.
